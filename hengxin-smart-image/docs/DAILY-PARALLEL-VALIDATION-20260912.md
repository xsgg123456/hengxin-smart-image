4. 用实际生产 Bubblewrap 挂载执行双向读写探针，检查结果归属与图片字节，记录失败原因，复查服务和进程收尾。

## 失败定位

A 的播报记录表明第二张因重复镜头重做。最终会话目录中有五张原生候选图；`manifest.json` 含 slot 0–3，各自选择不同文件。四个所选文件都存在于自身会话目录且可解码，但还有一张未被清单选用的候选图。

对保留文件只读调用现有 `collect_outputs`，稳定复现 `output_count_or_manifest_mismatch`。`backend/app/execution/output_collector.py` 要求清单文件集合与本轮所有新文件集合完全相同，因此额外候选图导致整轮拒绝。对外错误统一成了 `OUTPUT_MANIFEST_INVALID`，用户只看到“输出清单缺失或不符合约定”。

这属于候选图与最终交付清单的契约兼容问题；本轮没有证据表明串行调度、会话串用或跨任务写文件导致失败。现有校验规则尚未修改；A 保留真实失败状态，不伪造发布成功。后续应明确按最终清单验收的规则，保留逐图来源/新鲜度/链接/目录边界校验，并将多余候选与清单无效区分诊断后再做真实回归。

顺带核对此前两组任务：原“2-1”与“2-2”确实串行；配置调整后的“2-1-retry”与“2-2-retry”时间重叠约 4 分 49 秒，后者也是五个候选、四个清单引用导致失败。不能用原串行记录替代当前环境状态，也不能把 CLI 退出 0 当作业务成功。
