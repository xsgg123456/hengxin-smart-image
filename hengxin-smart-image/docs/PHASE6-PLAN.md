# Phase 6 执行计划

依据：DEV-PLAN Phase 6、Product-Spec REQ-003、第 7/13 节；2026-09-09 用户授权继续 Phase 6，承接 Phase 5 验收。

1. 用户与权限基础：建立稳定用户 ID、服务端显式开发身份、四角色策略及共用删除审计。验收：匿名、停用、待授权拒绝业务，客户端不能伪造身份，生产启用开发身份拒绝启动，跨创建人共享访问符合矩阵。
2. 文件存储：JPG/PNG/WebP 单张最多 10 MiB，服务端完整解码，记录尺寸、类型、哈希和所有者；私有 MinIO 原字节存储、受控预览及下载。验收：空/损坏/伪造/超限图片拒绝，上传失败不产生可用记录，失败可重试；重启后文件及归属不丢失。
3. 前端接入：沿用现有登录、素材组件与 HTTP 适配，接入服务端身份与真实上传；未实现模板/Skill 不阻断独立素材上传，不伪造可生成状态。每组最多 20 张仍由素材组件校验，业务组提交的后端数量校验属于 Phase 7/8。
4. 四步验证：独立 code-reviewer 两阶段审查、权限/故障/边界测试完整性、后端编译迁移与前端类型构建、隔离 PG/MinIO 的真实上传下载/重启与浏览器回归，证据写 PHASE6-VALIDATION.md。

范围：钉钉真实认证、模板持久化、任务执行、ZIP、引用清理均在后续阶段。开发身份默认关闭，只通过服务端配置显式启用，测试资源不自动绑定真实成员。预览和下载每次经 API 校验身份并流式返回，避免浏览器持久化会过期的签名地址。文件保留原字节，不进行缩放；解码炸弹按 Pillow 安全边界拒绝。

分工：后端执行者负责 backend/ 内实现及测试；主 Agent 负责前端、infra/、文档和集成验证。独立审查由 code-reviewer 完成。各方不覆盖其他人的修改，不自行提交。

审查修复：上传在解析 multipart 前完成身份校验；读取流累计上限10MiB+64KiB封装开销，缺失/伪造Content-Length也按实收字节限制；文件自身仍严格10MiB。单请求仅允许一个file，不接收额外字段。
