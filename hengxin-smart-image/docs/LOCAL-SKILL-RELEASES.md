# 人工部署 Skill 与本地版本登记

本说明对应 Spec v0.25。代码交付不等于 VPS 已升级；部署前核对迁移、前端、API/Outbox 与原生 Worker 使用同一版本。本轮不自动迁移历史 ZIP，也不上传或改动线上业务素材。

## 责任与路径

管理员负责编辑、安装依赖及发布；平台负责登记、检查部署、显式启用、绑定和执行。发布目录由原生 Linux Worker 的 `LOCAL_SKILL_ROOT` 指定，默认 `/opt/hengxin-skills`，布局为 `<根目录>/<Skill标识>/<版本>/SKILL.md`。后台填写标识、语义版本、处理类型及说明，不接受任意路径。

不需要 ZIP。可以在服务器 Codex 中编辑草稿，或通过 SFTP/Git 传输目录；发布前将草稿整理到固定版本目录。编辑目录可写，发布目录不可由执行用户写入；管理员不能原地覆盖已验证版本。改变内容应使用新版本，保留旧目录供旧任务返工。

版本号遵循 SemVer，例如 `1.0.0`、`1.1.0-rc.1`、`1.1.0+build.1`，最长 100 字符。路径使用登记的完整版本号；`01.0.0`、空预发布分段等无效。

文件要求：根 `SKILL.md` 包含 YAML `name` 和 `description`；name 与登记标识一致。可选 `hengxin-skill.json` 声明 mode/version/requires，示例：

```json
{"mode":"wallpaper","version":"1.0.0","requires":{"executables":["python3"],"pythonModules":[]}}
```

元数据只声明依赖，不安装依赖。检查不会执行 Skill 自带脚本或调用模型；“已验证”表示部署探测通过，不表示图片效果已验收。脚本需要的 Python 包必须对实际隔离环境中的解释器可用，仅安装到 Worker 虚拟环境不代表 Codex 可以 import。

## 发布与后台操作

1. 在新版本目录准备完整文件；拒绝符号链接/硬链接、特殊文件和目录越界。用管理员身份将发布树及其父目录设为执行用户不可写，普通发布文件保持可读，必要脚本保留执行位。不要把 `/home/codex`、认证目录或整个系统目录开放给模型。
2. 配置原生 Worker 的 `LOCAL_SKILL_ROOT`。API 容器只登记数据，不需要挂载发布目录；不要依赖 API 容器检查宿主机路径。VPS 使用原生 Worker 处理检查作业，避免启动另一个不具备相同环境的队列消费者。
3. 在管理中心“登记版本”，可先登记后部署。点击“检查部署”，由 Worker 异步探测；首次成功记录完整文件树校验值并进入“已验证”。失败显示原因，修复未发布的部署后可重新检查。
4. 点击“启用”，再选择模块默认或模板专用版本。启用不会自动切换默认；切默认不会改变已保存模板，模板须显式重新保存/换绑。
5. 已验证内容发生变化时不得通过重复检查刷新校验值；恢复原内容或创建新版本。任务运行前再次校验，同一版本内容变化则明确失败，不自动回退。
6. “停用”阻止新任务使用；旧任务仍保留绑定，返工时读取并验证原版本。移除登记仅允许未被任务、模板或模块默认引用且无检查作业在途的本地版本，保留审计，不删除服务器目录。被引用目录也不能由管理员随意物理删除。

## 运行边界

每轮只读挂载本任务固定版本到 `/work/skills/{Skill标识}`，本地版本不从对象存储取包、不重新解包。新任务有独立 Home/会话；返工续接本任务会话，各轮素材目录独立。图片与结果仍按现有规则校验、保存，不把全局 `.agents/skills` 或发布根目录整体挂载进去。

只读挂载防止任务修改 Skill，不能阻止宿主机管理员以 root 修改或删除文件；管理员须遵守不可变发布约定。共享认证、服务器 CPU/内存和网络的既有边界不变。

## 升级、兼容与回滚

- 先备份数据库、原代码与运行配置，在无在途任务/检查时升级至迁移 `0012`，同步 API/Outbox、前端和原生 Worker。不要只更新前端或启动旧 Worker 消费新作业。
- 存量版本来源为 `zip`，原对象地址与包校验值不变；旧任务仍走原解包执行路径。公开新 ZIP 上传入口关闭，历史安装/执行兼容保留。
- 本地目录校验值与 ZIP 校验值含义不同，不能用目录哈希覆盖历史包哈希。历史迁移到本地目录需独立的数据迁移和任务引用核验，本轮不执行。
- 备份必须新增 `LOCAL_SKILL_ROOT` 的发布版本树，并继续备份 PG、对象存储及必要任务会话。只备份数据库不足以恢复本地 Skill 任务。
- 一旦登记了本地版本，不得直接回滚到只认识 ZIP 的旧业务代码并继续接单。先停止新任务准入、完成/妥善处置在途工作，再采用兼容版本回滚；数据库降级限制以 0012 迁移脚本为准，不删除记录强行降级。
