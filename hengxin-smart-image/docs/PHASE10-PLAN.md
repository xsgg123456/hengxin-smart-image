# Phase 10 整套与单张返工

2026-09-10 用户授权开始下一阶段，Phase9已验收；依据 Product-Spec REQ005、9.1–9.2、AC006/007/010/015/016/021，DEV-PLAN Phase10。复用现有Art详情抽屉、ResultCard、意见弹窗、版本选择、执行记录。

1. 返工接口：开放 POST /tasks/{id}/rounds，必须携带幂等键，复用任务行锁与未结束轮次约束。普通返工冻结意见和slot；显式retry沿用当前已确认失败轮次的范围与意见，过期请求拒绝，待核实不可重试。四角色可操作全员任务，记录真实操作者。验收：202异步、重复键同回执、同键异内容409、跨用户并发只受理一次。
2. 前端提交：沿用详情UI，接入服务端资格，按用户和任务保留草稿/请求快照/幂等键/受理回执。未知响应只重放原请求，401重登、关闭重开和意见编辑不静默换键；冲突保留意见。验收：双击只建一轮，受理后离页继续执行，旧图和历史可看，错误/空态明确。
3. 结果与执行：单slot成功只更新该slot；失败保留旧版本，整套部分成功逐slot发布可信结果并显示部分失败。复用固定Skill、素材、session；不新建替代会话。验收：其他slot对象键/hash不变、失败旧图不变，过期token/删除不发布；模拟覆盖状态，真实CLI返工效果按原计划Phase14验收。
4. 独立验收：Linux PG/Redis/MinIO/Worker隔离回归及多人竞争，前端类型/单测/构建/真实浏览器；独立两阶段审查和匹配快照通过，用户确认后完成。不提交或部署生产环境。

本期无新外部依赖、无新设计风格；不提前实现Phase11归档及Phase13统计页面。历史版本与部分失败按既有Phase10交付清单实施。

状态聚合：单张本轮成功不等于整套完成；其他slot缺图或仍有未解决错误时任务继续显示部分失败，列表筛选与ready计数必须一致。轮次本身仍如实记录该次成功，只有所有slot完整无错才展示整套待查看。

普通返工意见为1至1000字符；retry必须携带当前失败轮次的sourceRoundId，目标与意见完全冻结（原首次意见为空时允许沿用空意见）。CLI已有会话记录但缺少ID时，仅所有历史尝试均已结束且无进程ID才允许重试首次初始化，否则拒绝替代会话；尚无会话记录的已确认失败允许重试首次执行。执行器类型沿用原任务。
