## 日常使用

独立发布生成原生服务配置时，只替换既有 `90-unified-source.conf` 的 `WorkingDirectory`，逐字保留发布门禁和国内工作台目录等其它配置。原配置结构异常时在准备阶段拒绝；候选摘要、原配置备份和恢复校验保持启用。2026-11-13 显式 Skill 发布首次尝试暴露旧工具覆盖这些配置的问题，已先经 `recover --scope domestic` 恢复原版本，修复验证后重新准备发布。

本地先提交已审代码，从明确Git提交构建目标包；未提交工作区内容不会进入包。国内用 `domestic`，国外用 `overseas`，共享前端用 `shared`：

```powershell
python scripts/release/intranet/package_release.py --commit HEAD --scope domestic --output output/release/lan-domestic-日期-提交号.tar.gz
```

用项目现有内网传输方式上传到 `/opt/hengxin-lan/` 的新版本专属文件名，核对SHA256，不覆盖以前的包。登录内网服务器执行：

```sh
TOOLS=/opt/hengxin-intranet-tools/current/scripts/release/intranet
python3 -B "$TOOLS/stage.py" /opt/hengxin-lan/lan-domestic-日期-提交号.tar.gz --name lan-domestic-日期-提交号
python3 -B "$TOOLS/release.py" prepare --scope domestic --mode full --release /opt/hengxin-unified-releases/lan-domestic-日期-提交号
python3 -B "$TOOLS/release.py" deploy --scope domestic
python3 -B "$TOOLS/release.py" verify
```

仅前端改动用 `--mode frontend`；本组后端发生变化会拒绝。完整Git包中可包含其它业务已变更的独占Python文件，但必须在旧/新依赖图均证明目标业务不加载，仍只挂载/重启选中组。未知归属和跨业务公共变更拒绝。

```sh
python3 -B "$TOOLS/release.py" rollback --scope domestic
python3 -B "$TOOLS/release.py" status
python3 -B "$TOOLS/release.py" cleanup
python3 -B "$TOOLS/release.py" cleanup --apply
```

`rollback` 按一次新的目标组成功部署登记，保留回退后当前版和回退前上一版，自动清理；国外记录不变。`cleanup` 默认预览，`--apply` 执行或重试清理。

中断后用 `recover --scope domestic` 恢复当前事务并验证；仅准备未切换可用 `cancel --scope domestic`。有未解决事务则禁止新发布或清理。所有命令复用原发布锁，独立发布不等于并发改写同一compose。

台账 `/var/lib/hengxin-release/intranet.json` 使用version 2，各组current/previous独立；事务及数据库备份在同目录 `intranet-transactions/`，私有权限，不输出凭据或提交Git。源码清理仅限已接管 `/opt/hengxin-unified-releases/`，未知遗留目录保守保留。

## 国内工作台联合升级（开发中，尚未安装或执行）

本次共同后端及国内 schema 0032→0043 不能使用普通单组发布。联合升级实现复用当前发布锁和 version 2 台账，对三套同一 Git 提交的已暂存包校验依赖、迁移链、服务身份和配置；关闭入口并排空后备份，再执行国内迁移和联合切换。海外 schema 与数据容器身份必须保持不变。

`joint_studio_release.py` 提供 `prepare`、`deploy`、`recover`、`finish` 和 `status`；它与普通发布和清理共享中断标记。迁移前可恢复原服务；迁移提交后只进行前向恢复，不能自动倒灌数据库或恢复旧代码。新发布服务和锁目录由受保护配置固定，并检查开机重建 socket 目录的规则。该流程仍需独立审查、真实安装验证和正式执行；此段不表示生产已经切换。

候选阶段将三个 API 限定在各自容器回环地址、网关限制为容器内回环访问，均不发布宿主端口。`/var/lib/hengxin-domestic/release-gate` 中的 `workers`、`ingress` 由 root 持有并以只读目录挂载到应用；原生服务通过同一路径读取。候选启动时两个标记保持关闭，后台清理、消息生产和消费均等待，凭据 socket 自创建起无访问权限。从容器内核验源码、身份和三个前端后登记台账，再以正式监听验证前端和只读健康接口；业务请求仍返回维护状态。全部核验后恢复凭据和后台，后台验活通过才最后开放业务请求。部署进程在此前异常退出不会自动打开标记。

核验或开放失败时先持久关闭业务请求、停止入口，使用既有排空机制和禁止强杀的停止配置结束后台，再关闭后台标记；中断后凭标记及事务前向恢复，不能手工写 `open` 绕过核验。两个开放标记保留供后续服务重启读取，普通独立发布保留相关环境和挂载。安装后使用独立标记的 Docker 测试资源验证网络和请求、后台封控，再执行正式迁移；不得把测试通过视为生产已经升级。

凭据服务重启前，协调器检查两个服务已停止、MainPID 为 0 且存在的 cgroup 中没有残留进程；只处理原发布记录中的四个固定 socket 路径。遗留项必须是受控目录内、原服务 UID 持有的 000 socket，root 探测必须得到无监听者的 ECONNREFUSED，且探测前后的 inode 等身份不变，才移除后重启。目录链通过文件描述符和 O_NOFOLLOW 检查；活监听、未知文件/身份/权限和仍存活的进程均拒绝。该操作用于 accounts 保留目录中的异常遗留，不扩大到业务文件清理。
