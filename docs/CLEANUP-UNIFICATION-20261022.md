# 国内会话清理统一修复 · 开发验证后停止

用户明确授权根治自动清理失败、统一自动清理与删除任务的底层目录清理，测试和审查完成后停止；不提交 Git、不部署。此前换图记录筛选改动保持，不重做、不撤销；本轮不修改线上数据/服务，不手工删除失败目录或重置回执。

## 已查明根因

2026-10-22 线上两条 history/retry 会话含 `home/.codex/tmp/arg0/codex-arg0*/` 内的四类正常工具链接，目标为 `/opt/codex`。自动清理 `retention/paths.py` 拒绝所有链接，而删除任务的 `deletion_paths.py` 已能安全识别并只移除这些链接本身。线上同一代码以服务身份进行禁止删除复核，两条均抛 `ValueError: Linked cleanup material`，删除调用数为0；既有安全检查器两条均通过。证据在忽略目录 `output/retention-failure-20261022/`。异常又被 api.process 兜底吞成统一文案，难以定位。

## 修复与保护合同

1. 国内自动清理（缓存/历史）与显式任务删除共用单一底层目录清理组件。保持各入口原参数约定，业务数据库清理和对象回收职责不合并；海外行为不变。
2. 仅允许配置执行根内明确 UUID 的私有会话目录。生产 Linux 用目录描述符、不跟随链接及挂载身份检查，并在实际删除遍历的每层重复同一检查，使用 dir_fd unlink/rmdir；验证根/祖先/目标、挂载边界、文件类型及硬链接。合法工具链接仅在精确 arg0 路径、四个已知名称、目标 `/opt/codex` 全部匹配时允许，删除链接本身，不访问/删除目标。未知链接、越界、挂载跳转等继续失败关闭。Windows 本地测试保持保守拒绝链接/junction，不放宽生产安全边界。
3. 24小时缓存清理仅清 `home/.codex/cache`、`home/.codex/plugins`，保留其他会话文件；72小时历史清理才移除整会话目录。原图、素材、正式成品、所有采用版本、归档和调用/Token汇总保持原规则；其他任务/会话、共享凭据、外部程序及链接目标不得改动。
4. 保持执行保护、未确认状态保护、锁/屏障、每小时重试、25条批量上限和两阶段回收。失败不能假成功；允许已持久化 expire_pending 的失败记录下轮正常重试，不手工改状态、last_activity_at或成功计数。重试与重复调用必须幂等。
5. 对自动清理的历史/缓存、对象回收和扫描异常记录结构化脱敏日志：资源/对象标识、阶段、稳定错误码、异常类型及脱敏调用位置；不写提示词、文件内容、凭据、对象私有路径或原始异常消息。页面/API继续已有通用安全文案，不增加迁移或改变现有响应合同。日志能区分安全拦截、权限/IO、数据库锁/完整性、对象存储及未知异常。

## 后续发布依赖（当前不执行）

审查追加验收：不能只按 st_dev 判断挂载边界；隔离 Linux 实证同设备 bind mount 也会导向会话外目录，必须结合目录 FD 的挂载身份阻止 UUID 目标及其子目录的挂载跳转，证据不可读时失败关闭。配置执行根自身可以位于独立挂载中。一次性 worker 入口也必须脱敏并非零退出，不能在结构化日志后重新抛出原异常而输出完整敏感 traceback。两项修复后重新固定候选、重跑安全专项及全量回归、重新从 Stage 1 审查。

第二轮安全复核补充：预检后嵌套目录新增挂载也要在执行遍历时拒绝；仅预检后交给 shutil.rmtree 无法限制其重新打开的挂载，因此以同一安全 walker 同时支撑预检和实际 dir_fd 删除。worker.main 的配置、会话工厂、首次心跳和上下文关闭异常也纳入安全边界，不能只保护 execute_loop。

新共享模块必须包含在未来发布包；自动清理和显式删除的原生执行器都需安装同一修复代码。前一轮仅API/前端的 records 发布脚本不覆盖原生清理运行目录，不能当作这轮修复的发布入口。用户恢复发布前须适配实际消费者路径并重新验证，不能仅切HTTP API后宣称清理已修复。

实现依据：Python 3.12 [shutil.rmtree](https://docs.python.org/3.12/library/shutil.html#shutil.rmtree)、[os 的 dir_fd / follow_symlinks](https://docs.python.org/3.12/library/os.html#files-and-directories)。不升级依赖。

Linux 挂载身份依据：[内核 proc 文档的 fdinfo / mnt_id](https://www.kernel.org/doc/html/v6.8/filesystems/proc.html)，挂载身份与设备号是不同维度。
