# 草稿查询与锁竞争整改（2026-11-03）

用户已确认下列方案并授权开发、中文 Git 提交及生产部署。目标版本 0.2.61，数据库保持 overseas_0026，不修改历史业务数据、权限规则、Skill 或附件下载协议。

## 批准范围

1. 页面初始化读取一次；仅附件 queued/running 期间继续查询，前一次查询完成后等 2 秒再查，终态停止。查询去重、不积压；脏字段和保存优先，保留 500ms 防抖保存和本地恢复副本。
2. 页面隐藏暂停状态查询，恢复可见刷新一次；后台附件导入和自动保存不因隐藏停止。卸载、切换账号与旧代次的迟到结果不能覆盖当前内容。
3. 连续查询失败 3 次停止自动查询，提供明确手动重试。查询错误与保存错误分开，不以成功读取清除真实保存错误。保持版本冲突和未确认提交恢复保护。
4. 日常 GET 不再调用带 Member/Draft FOR UPDATE 的写入入口；同一次响应在一致数据库快照内读取字段、来源、附件、任务状态和设计师信息。账号归属与权限仍检查。草稿不存在时单独受保护初始化，并发首次访问仍只创建一份。
5. 保存、清空、提交、导入完成保留原写入锁、版本、代次、租约及幂等保护；网络与对象存储仍在数据库锁事务外。不承诺全库零死锁，不扩大为写路径重构。

## 实施顺序与验收

1. 前端控制器/页面：以真实控制器及组件测试证明空闲无持续 GET、导入自适应轮询、慢请求去重、保存优先、隐藏恢复、失败暂停重试、迟到响应及本地恢复不丢字段。
2. 后端读取：普通/权限/首次初始化测试；真实隔离 PostgreSQL 测试证明慢 GET 不持上述行锁、不阻塞同账号保存，跨查询字段与附件快照一致，以及导入完成与清空/提交并发保护。
3. 全前端回归、类型与构建；后端相关及海外回归，独立候选快照两阶段审查。必要发布脚本同批审查，制品安装测试不得跳过真实 PG 验证。
4. 已审中文提交后构建固定包；复查生产实际基线、排空/备份、最小 API 与前端更新，不改 schema/native 源码。保留回退制品及原配置；正式页面检查无空闲轮询、草稿恢复、附件显示和国内/海外健康。不得为验证创建正式任务或触发生图。

风险控制：一致快照避免旧字段配新附件；首次创建保护避免重复草稿；状态延迟由可见恢复刷新和手动重试补足；已有正在执行的单次 GET 无法抢占，但不允许积压更多 GET 延迟保存。必要写锁仍可短暂竞争。
