# 累计生成统计与分页生产发布

用户明确授权先提交Git，再打包部署生产并核对统计和分页，保护在途API任务。本轮为已验收功能的正式发布。

## 发布步骤与完成标准

1. 提交已审功能与需求/验证文档，保留预存无关skill修改。发布增量升级前端0.2.21并审查打包部署工具后单独提交。
2. 白名单打包已提交代码和生产构建，审计隐私、依赖与SHA256；上传服务器构建镜像，断网跑安装测试，检查运行镜像内文件哈希。
3. 发布前备份前端入口、版本标记与compose配置；数据库只读核对，不迁移、不回填、不修改任务或通道。API容器按既有配置只替换镜像并等待健康，随后reload Nginx恢复服务发现并原子切换前端入口；保留旧静态资源。API进程只提供HTTP请求，执行任务由独立服务处理。
4. 全程保持api-image-worker、api-image-outbox、outbox、image-variants及原生CLI执行器不重启，以容器ID/StartedAt、原生PID/启动时间验证。保留原API镜像与compose路径，失败只回退Web API和前端，不触碰运行任务。
5. 安装后真实只读管理员统计校验累计=首次+修改、日报和事件生成量对账、默认全量；20/50/100真实列表分页与筛选核对。验证公网入口与资源哈希、匿名鉴权、API readiness，复查任务与执行器。真实用户登录态不可用时不冒称已完成钉钉登录UI验收。
