## 统一实施口径

- 管理统计只读API业务，不再混入旧TaskRecord。保留旧统计接口兼容旧客户端，新增 `/management/api-usage`、`/management/api-monitor`、`/management/execution-settings`，新管理页面使用新接口。用户/角色、Skill及原有设置保存权限维持。
- 任务按创建、请求按尝试开始、CLI按真实启动、候选按落库、正式版本按发布、采用按用户采用时间分别归北京时间自然日。当前库存只按创建人员过滤，不受历史日期/操作类型筛选；UI必须显著标明此区别。
- API请求尝试包含失败重试，排队/预检不计；CLI启动与提交分开，未能证实启动的历史记录显示证据不足，不冒充调用。CLI正常澄清文字完成不算生图失败；候选成功不等于采用。
- 请求返回成功率只使用已知成功和失败的请求，未知/在途单列。当前图片交付成功率按最新图片处理状态：succeeded/(succeeded+failed)，排队/运行/收图/待核实不入分母，与历史请求成功率显著分开；旧结果可保留时另显示有正式结果图片数，不混淆最新处理失败。
- 历史生成正式版本、CLI候选、手动采用、恢复版本分别计数。恢复不增加模型调用/生成数量。Token费用无完整可靠证据显示未提供，不推算。
- 历史正式版本来源无法证明时单列“来源待核实版本”，不计已知生成或采用。CLI提交事件固定表达“已提交”，执行轮次结果随终态及采用更新，避免回填时的运行状态永久残留。
- 实际操作者归属：新重试冻结发起者供后续尝试使用，不能改写以前尝试。旧记录只有登记操作者，标历史归属未核实；不从提示词/事件文本猜。历史kind无法证明时为legacy_unknown。
- 轻量事实记录与源执行事务共同维护，键幂等，无提示词/图片字节/会话正文，不外键依赖可清理的过程表。GET不写统计，历史原始记录与事实按源键去重读取；提供幂等回填命令，清理会话前强制保全对应事实，清理/软删除不得令历史缩水。缺失历史不造数。
- API生图、CLI修改分渠道监控，真实独立Worker心跳；新心跳未就绪/过期时显示未知，不用CLI心跳冒充API服务在线。数据库业务队列计数与执行服务健康分开，收集失败显示unknown不填0；跨阶段任务不可相加，当下运行数不是并发上限。
- 配置从实际配置/调度常量读取：API/CLI参数分区，API只读，原CLI设置表单继续可保存且明确仅后续轮次生效。保留钉钉/Skill绑定和配置审计，不把它们当API业务数据。
- 清理规则继续在配置页只读展示，直接读取清理开关与1天/7天策略常量；开关不等同清理服务已在线，页面不提供开启生产清理的操作。
- 保留最新菜单权限：普通角色管理入口仍关闭，但后端统计个人范围检查继续生效。管理员/主管全员；前端任务跳转到API记录详情，已删除任务明确标注不误跳旧中心。

## 交付顺序及验收

1. 统计事实模型、0025迁移、业务采集、历史投影/回填、清理前保全；验收重复回调/回填幂等、跨人员重试、真实启动、删除及7天清理后统计仍在。
2. API统计聚合与权限/日期/类型查询，真实双渠道监控和配置读取；验收汇总等于明细、跨日、未知不变0、任务/图片/调用不混量纲、敏感配置不返回。
3. 前端继承既有预览布局接真实接口，mock场景仅显式mock/demo模式，正式无模拟回退；筛选、分页汇总、明细跳转和配置保存回归。
4. 隔离SQLite/PG迁移和并发验证、前端单测/类型/构建/实际浏览器、后端API业务回归、独立两阶段审查。只本地实施；不调用收费模型、不执行生产写入或部署。生产上线另行确认。
