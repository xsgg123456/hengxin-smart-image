# 内网国内、国外独立发布（2026-11-11 已批准）

用户授权按已确认方案实现、测试、独立审查并部署内网。复用已有工具，不新造第二套发布/回退/清理体系。仅操作192.168.1.245，不操作旧公网。

1. 国内、国外、共享（登录/账号/授权）分别记录当前、上一成功完整版本；单侧发布和回退不改变另一侧版本、进程或队列。共享组件变更明确识别，不能借国内发布偷偷影响国外；跨域公共代码变更必须明确联合发布，不误判为单侧。
2. 扩展现有 release.py prepare/deploy/recover/rollback/cleanup 与共享锁、engine事务及snapshot验证；保留现有源码、镜像、文件GC的安全证明/引用扫描/失败续清。锁仍串行，独立发布不等于同时修改同一compose。
3. 前端在同一IP/端口下分国内/国外/共享独立产物和静态服务，复用现有页面、身份API及组件；不重做UI。地址前缀 /domestic/、/overseas/、/shared/，旧hash链接兼容跳转；同源登录不变，跨业务切换和登出不得循环或留下失效会话。静态资源带各自前缀，已打开旧页面的资源受保护。
4. 首次迁移先新增静态服务并验证，再切网站入口及登记分组基线；业务后端/worker/身份账号服务保持现有进程和源码路径，数据库/Redis/MinIO不迁移不重建，不能暂停或杀正在执行的任务。入口可短暂切换，但必须有原配置、原入口和原台账回退，迁移未验收前不清旧版本。仅替换静态入口，禁止顺便重发后端。
5. 后续单侧后端发布复用既有排空与事务恢复，作用域限制所有stop/up/systemctl/队列指令，只处理目标侧。排空失败则恢复接入并退出，绝不强停运行任务；国内发布不得关闭共享账号/授权socket或暂停海外队列。跨域共享后端升级需要明确联合维护，不能默认为日常单侧操作。
6. 成功验证后仅推进被发布组的两次成功记录；每组各保留最近两次，不按全站最近两次挤掉长期未发布侧的上一版。GC保护所有组current/previous、未完成发布、全部实时引用，仍不删业务数据。失败不推进，清理错误不回滚已成功业务。
   新前端包只兼容上一成功版本自身的静态资源，不把更早兼容资源逐代复制，避免只剩两个目录、目录内部却无限累积。
   每组静态服务另只读挂载切换前的前端，当前asset缺失时回源该挂载，未知asset返回404。回退C→B时不修改B历史包即可兼容仍打开C的页面；下次发D改挂B，C不会因旧兼容挂载永远保留。实际挂载及清单纳入快照核验和引用保护。
7. 独立回退从当时仍运行的全站配置合成目标侧变更，不能恢复整份旧compose从而覆盖另一侧后来成功的发布；回退不回滚业务数据库。首次迁移不伪造新旧成功版本，原真实旧版记录保留供回退。

执行与验收：
- 日常命令支持国内/国外完整发布和三组各自前端发布；共享后端及跨业务公共代码的联合维护不在此次静态迁移内，命令明确拒绝，不能假装已提供安全的共享后端热更。
- 先更新范围合同/Spec/计划，核对内网基线与任务只读状态。
- 分离前端产物/跳转；扩展作用域执行/快照/台账/回退和GC，复用打包/运输/安装。
- 隔离覆盖国内→国外→国内交错发布与各自回退、同镜像版本推进、失败/中断/排空失败、共享更改拒绝、跨域引用GC和旧地址/登录/页面资源；Python与前端类型/测试/构建，真实Linux测试与独立两阶段审查。
- 首次迁移部署只切静态入口，前后对比原应用和数据容器ID/启动时间、7个原生PID/启动时间、镜像/配置允许变更清单和运行任务只读状态；正式入口浏览器验收。测试不得写真实业务记录或调用收费模型。留存精确证据，未测试的不宣称通过。
