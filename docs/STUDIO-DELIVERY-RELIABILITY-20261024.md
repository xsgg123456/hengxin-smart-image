## 实施步骤与验收

1. 统一最终消息识别：对齐正常退出回执和当前执行精确事件边界，中途确认不是终态；重试不读取后来轮次。最终文字引用不受无关原生事件解析故障阻断。验收真实确认消息和八条历史 JPG 引用。
2. 保全交付：在后端私有控制目录保存最终回复、选中路径、逐图字节和摘要，原子提交并落盘。保全过程未完成前保持原任务活动状态，禁止后续轮次覆盖；重启先恢复原收图，不启动模型。捕获失败保留恢复依据和原目录。
3. 持久补收：复用既有 Job/Turn 和对象台账，使用确定性图片身份、逐图提交和恢复租约。存储成功但数据库失败可重放；只上传缺失项。当前轮图片关联与数据库记录原子提交。取消、任务/会话删除和失效租约不能发布迟到图片。
4. 状态与展示：收图未齐维持保存中并显示实际数量；已保存图片立即可见；全部保存才交付完成。自动补收有退避，不产生重复对象、图片或模型调用。后续轮次重新交付同一图片可以产生独立交付版本，避免共享对象删除影响历史。
5. 验证：最终回复混合文字/图片、无固定标题、历史 work/native、原生附图、17 过程图只取最终 8 图、缺文件、单图存储失败、上传结果不明、数据库失败、崩溃重启、迟到租约、取消删除、路径安全及原图哈希。独立审查失败则修复重测。
6. 发布：只读核对当前 API/worker/outbox 与 Skill 清单；备份、停止接纳并排空后更新实际安装产物，验证安装专项、健康和现有任务入口。原八图补回按上述用户更新取消；不得复活已删除任务。恢复接纳，提交推送已审文件，不包含用户 AGENTS.md 改动。
