# 恒鑫智图 · 产品与 UI 优化计划

日期：2026-09-21。状态：2026-09-22 已开始实施核心交互修复批次；用户已批准正式前端 UI 迭代并授权部署；不改变既有 Phase 验收结论，部署完成须有发布证据。

## 1. 目标与依据

优先让设计与运营人员完整看清图片、快速浏览整套结果、理解任务状态并继续操作。保留现有红色品牌、蓝色操作主题、Art/Element Plus框架和三个独立处理页面。

依据：Product-Spec.md、Design-Brief.md、DEV-PLAN.md；output/ui-audit-2026-09-21/完整审查报告.md及图片专项复核.md。后者对加载中截图和图片交互的修正优先。审查累计21项是历史观察，实施前复核当前页面与部署状态，已修复项不重复改。

产品范围冲突说明：现有Spec明确本轮不制作Skill、不作图片效果评测；商品/文字Skill属于上线外部就绪条件，不自动纳入本次UI开发。不改变现有全员资源范围，不新增审批流、复杂图片编辑器或完整移动编辑。

## 2. 推荐执行顺序

文档同步 → 第一批图片浏览 → 第二批任务详情 → 第三批创建与模板工作流 → 第四批全局视觉与管理页 → 第五批真实验收。

Skill就绪、普通角色账号、真实测试素材可与UI工作并行准备；它们未就绪不阻塞图片浏览改进，但阻塞对应能力的最终上线验收。

- 将比例、间距、字体、状态和预览交互同步Design-Brief.md；本计划给出的新布局是拟定方案，不冒充已经认可的设计稿。

完成标准：每个交付项都有需求编号、具体页面、可验证标准；生成质量及新Skill工作与UI边界清楚。

### 第一批：图片完整展示与统一大图浏览（最高优先）

对应 U19/U20/U21；承接 REQ-002/003/005/006。

交付物：
1. 统一图片缩略图与加载状态：业务图完整等比适配，方图默认方形框，长图保留留白；加载中保留框和占位，失败显示重试，不把空白作为完成状态。
2. 统一整组预览：模板选择、摘要、模板库、上传预览、模板编辑、历史、任务原素材、结果及成品入口接入同一套规则。点击图片只预览，选择/使用模板是独立动作。
3. 补齐结果连续审阅：鼠标左右箭头、键盘左右、序号总数、文件名、尺寸与版本；保留缩放/旋转，Esc关闭并恢复原焦点和滚动位置。

拟定交互规则：
- 套图卡最多露出4张完整缩略图，超过4张显示“+N”，所有图片仍可在预览到达。较窄布局减少同排卡数，不把图片无限缩小。
- 点击第k张从k/N打开；单图不显示左右切换；多图建议首尾停止并禁用对应箭头，避免不知不觉循环。
- 默认结果集合按槽位顺序展示当前版本。若某张切至历史版本，预览该张采用所选版本，其余位置采用当前版本；页内明确版本，下载/归档仍遵守既有当前版本规则。
- 失败/无结果槽位保留顺序与状态，不能悄悄重排编号；预览可继续切到其他有效图。预览内不新增下载/归档入口，避免操作的版本语义混淆。
- 图片默认完整适配，用户可主动放大检查细节；切换图片重置为完整适配；预载相邻图，不一次加载整个大图库原图。
- 大图置于顶层，避免被抽屉/弹窗裁切；关闭大图只关闭预览，不误关父弹窗。

关键文件（相对 hengxin-smart-image/frontend/src/views/hengxin/）：
- 拟新增 components/ImagePreview.vue、components/ImageThumbnail.vue、image-preview.ts，封装现有预览能力与统一数据规则；名称为计划新增，非现有文件。
- 接入 components/CreateTask.vue、Templates.vue、ImageUpload.vue、TemplateEditor.vue、TemplateHistory.vue、TaskSources.vue、ResultCard.vue、TaskDetail.vue、Archive.vue。

验收：
- 1/4/20张，方/横/竖图；可辨识边框与四角标记的测试图均完整显示，页面不横向溢出。
- 从第2张打开显示2/4；鼠标和方向键往返正确；预览不改变模板选择和版本绑定。
- 网络慢、单张失败、403/过期资源不显示无解释空白，其他有效图仍可查看；不记录带鉴权参数的图片URL。
- 现有模板编辑/历史切换不退化，结果图及成品补齐同样能力。成品和多素材用专用测试数据验证，不用空库推断通过。

### 第二批：任务详情以结果和恢复为先

对应 U03/U04/U05/U08；承接 REQ-004/005/006。

交付物：
1. 成功详情顺序：状态与结果数量 → 结果网格 → 修改/下载/归档操作；执行日志、绑定及原素材收进有入口的次级区域。
2. 失败详情顺序：失败摘要 → 原因 → 可执行下一步 → 已有成功图；处理中仍保留可见进度与最近活动，不把所有过程信息一律隐藏。
3. 区分恢复动作：可重试错误提供重试；需换素材的错误引导带入任务信息新建，明确用户需补的素材；不改原任务输入、不把新任务伪装成原轮次续接。

状态文案：成功展示“已交付4张”；候选数量放诊断区，如“发现5张候选，目标4张”。“待查看”说明为业务待处理状态，不与生成成功冲突。

关键文件：components/TaskDetail.vue、ResultCard.vue、ExecutionProgress.vue、TaskSources.vue、TaskTemplate.vue、execution-presentation.ts、use-task-detail.ts、use-create-task.ts、task-creation-session.ts、task-state.ts。

依赖与边界：缺料分类优先使用已有结构化结果；若接口没有可靠分类，本批先提供明确“换素材重新创建”入口及原始原因，不通过匹配模型播报中的关键词自动判定错误类型。新增后端错误协议需另列契约变更，不伪称纯前端可完成。

验收：1366×768首屏能知道成功/失败/处理中及下一步；历史图与当前图不混淆；失败保留已有结果；旧任务链接、关闭返回、列表筛选恢复均不退化；不会自动重复提交。

### 第三批：创建任务与模板维护减负

对应 U06/U07/U08/U11/U12/U15；承接 REQ-001/002/003。

交付物：
1. 创建页模板选择采用紧凑已选摘要＋更换入口；没有选择时才展开选择区，让上传与任务信息更早出现。提交区明确待完成项，错误定位到相关输入。
2. 能力不可用时在标题下说明原因；超管直达配置，普通用户得到真实联系途径。保留用户已填内容，不显示可成功提交的假象。
3. 模板卡以预览/使用为主，维护动作放更多菜单；编辑弹窗限定高度、正文滚动、底部保存固定，图片顺序与删除确认保持可理解。

关键文件：components/CreateTask.vue、Templates.vue、TemplateEditor.vue、ImageUpload.vue、WorkspaceStatus.vue、use-create-task.ts、task-creation-session.ts、use-image-upload.ts。

验收：选择/换模板不误清空已填素材与任务信息；真正影响输入兼容性时说明原因；20张图片情况下保存按钮持续可达；首次无数据与搜索无结果有不同下一步；未就绪模块不能错误提交。

### 第四批：统一视觉与辅助页面

对应 U09/U10/U13/U14/U16/U17/U18，补齐U08/U15。

交付物：
1. 视觉规范：保持红品牌和蓝色动作，统一辅助文字、图框、间距、圆角、焦点和悬停反馈。业务说明拟采用14px，标签/次要元信息不小于12px，标题沿用现有体系；普通小字对比度目标至少4.5:1。字号须同时检查100%及200%缩放，不靠颜色单独表达状态。
2. 业务信息：任务列表补提交人及“我的/全部”视角，缩短编号并可复制；Skill长标识放技术详情，使用中文业务名称；登录文案说明用途与权限求助。
3. 管理页面：统计数字分组和时长可读化，空部门使用明确占位，默认Skill以Skill管理为主入口，系统配置展示当前值及跳转，保持服务端数据语义。

关键文件：components/Tasks.vue、use-task-list.ts、list-location.ts、model.ts、components/Templates.vue、Archive.vue；admin/usage.vue、users.vue、settings.vue、SkillDefaults.vue、skills.vue；frontend/src/views/auth/dingtalk-login.vue（路径以既有计划为基准，实施时确认）；共享主题样式的现有实际入口在开工前定位后修改，不另造并行主题。

依赖与边界：若任务接口缺提交人/人员过滤，不在当前页结果上伪装全库筛选；另列服务端字段与查询契约任务并验证分页总数。默认绑定调整只整理入口，不改变已保存模板固定版本的业务规则。

验收：浅/深主题、1280×900、1366×768、1440×1000和200%缩放；导航及焦点清晰，无新增横向溢出；未授权账号不能因新增入口获得权限。

3. 独立代码审查、发布与回退凭据；2026-09-22 用户已授权本轮正式前端发布；按发布记录执行，保留后端、Worker 与数据库。

每批完成门槛：代码审查、测试完整性、类型检查/构建、实际浏览器功能验证全部通过。按项目harness review-prepare固定candidateId，code-reviewer两阶段复核，批准同一快照后才能提交交付；存在代码变更需重验相应差异。

有意义的回归覆盖：图片顺序/起始索引/当前历史版本/错误槽位；关闭层级与焦点；未提交草稿；分页/筛选URL；失败恢复防重；归档冻结版本与授权下载。不为单纯颜色或可逆文案改动编写镜像测试。

截图门槛：先确认业务图片节点和预期数量，再等待complete、naturalWidth>0、decode成功及可见尺寸。懒加载图逐区域触发加载；加载失败单独留证，不无限等待、不将失败遮掉。不能用networkidle或固定sleep替代图片完成判据。

## 5. 技术复用核对

沿用项目锁定的Vue/Element Plus，不为此升级框架。现有模板编辑/历史已实证支持整组预览，优先复用并统一接入。官方Image文档确认图片fit、preview-src-list和initial-index支持完整适配及从指定位置预览：[Element Plus Image](https://element-plus.org/en-US/component/image.html)。文档查阅日2026-09-21；在线文档可能含高于当前依赖版本的API，实施仅采用本地锁定版本已支持的能力，元信息/占位不足之处在业务封装补齐。
