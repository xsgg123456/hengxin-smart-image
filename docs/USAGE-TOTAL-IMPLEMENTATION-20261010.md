# 累计生成图片与分页正式实施

用户已拍板独立预览并授权正式开发。本轮本地实现与验证，不部署生产，不执行收费生成。保持 API 换套图的生成、修改、采用、恢复、下载及权限逻辑。

## 口径与界面

- 沿用预览和既有前端。首屏四项：累计生成图片、首次生成图片、修改生成图片、生成任务数。默认全部时间、权限内全部人员、全部生成类型；重置恢复全量。原图库存整个展示块移除。
- 累计 = 首次 + 修改，10+3=13。首次是成功的 API generation 正式版本；修改是成功的 API 修改版本（image_edit/text_edit/text_repair/revision）和 CLI 成功产出的候选。CLI 未采用候选也已是生成产出；采用、恢复、失败、仅文字回复、素材上传不再累计。任务数是当前筛选范围有生成产出的去重任务数，不是新建任务数。
- 沿用统计事实唯一键和只读历史投影；日报与总数同源，详情标明每条计入的生成图片数。已删除任务、七天过程清理不减少已保留累计。日期按图片产出事实时间及北京时间分组，人员按真实操作者或历史登记人；未知归属如实标记。
- 历史来源不足的版本不能猜成生成或采用，保留“来源待核实、未计入累计”的数量说明。已有 inventory 接口字段为兼容保留，但不用于新界面、不得以库存冒充历史累计。
- 新增 generationType 筛选 initial/api_edit/cli_edit，与既有事件筛选兼容。API 请求按已知 kind 归属生成类型，CLI 提交/执行/候选归 cli_edit；业务成果详情只展示有产出的事实，执行消耗可看同范围全部事件。对无法证明类型的历史请求不强行分类。
- 换图记录真实请求 pageSize 支持20/50/100，默认20，改变后回第一页并保留状态/搜索。删除后页码纠正按当前pageSize。日报也使用预览的20/50/100分页，总数不随页码改变。

## 有序实施与验收

1. 后端新增 summary 初始/修改/累计/生成任务字段及生成类型、产出事件筛选；单测与真实隔离事务覆盖10+3、采用/恢复不重复、历史未知、权限、日期、删除、清理、分页。
2. 前端更新契约/校验器、调用统计与明细；换图记录接动态pageSize。复用已审预览视觉及现有错误/加载/空态。单测覆盖默认全量、字段校验、筛选重置、分页、错误重试。
3. 前后端完整测试、类型及正式构建、隔离真实后端浏览器验证。实际生成/采用/恢复/清理路径由隔离测试替身验证，禁止生产写入。保存命令与结果。
4. 固定快照并独立两阶段审查，修复后复核；交付本地结果与证据，生产待确认。
