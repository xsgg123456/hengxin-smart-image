# Phase25 全流程与交付验收合同

Phase24提交后实施，不自动部署或调用收费模型。以DEV-PLAN Phase25为目标，前四阶段实际代码为验证对象，跳过与外部未验能力单独记录。

1. 用随机命名临时拓扑运行统一身份、国内API、海外API、独立数据库/Redis/私有对象存储。五角色与兼任身份串联提交、分析、确认、多SKU生成、部分失败恢复、单图标注返工、审核归档、改派、统计和配置；CLI使用明确标注的离线真实子进程替身。浏览器使用真实API、真实图片与下载，验证宽窄屏及无权限/空/错/冲突。
2. 复验资源级隔离：生产式独立应用凭据不能读写对方库/桶/Redis，任务派生资料/方案/图片历史/归档/事件按当前权限检查，停用与改派即时生效；五并发上限含未知进程占位，重复/租约失效/取消/竞争不能产生重复交付。保留国内哨兵记录与对象哈希。
3. 备份恢复在临时环境演练：独立数据库逻辑备份恢复后记录/方案/图片版本/归档一致，对象恢复内容checksum一致；不读取生产凭据和数据。说明Redis是传递层、数据库outbox可补发，未知进程不可盲重跑。
4. 全量前后端测试、类型、编译和正式构建，形成可复跑命令入口与证据清单，列明旧宿主条件跳过项、真实钉钉/收费图片质量/生产配额等未验范围。输出部署检查清单：配额、独立账号和目录、初始管理员、备份、私有访问、迁移、排空/回滚、保留策略；自动清理保持关闭。
5. 同一代码快照独立Stage1/2审查通过，批准后本地中文Git提交。交付汇总Phase21–25五次提交与验收结论。
