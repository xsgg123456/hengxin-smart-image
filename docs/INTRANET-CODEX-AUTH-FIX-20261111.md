# 内网 Codex 授权代理修复

用户报告国内 Codex 登录弹窗显示“授权未完成，请重新获取授权码”。只修复 `.245` 内网副本，旧公网保持不动。

实查：账号服务日志显示 `device code request failed with status 403 Forbidden`；父服务具有 HTTP/HTTPS/ALL_PROXY，但 `device_login` 构造最小子进程环境时未传代理。以同一真实服务 UID、同一 0.167.1 二进制和现有解析器对照，仅补传代理即成功取得授权码；诊断在取得码后取消，没有登录、启用或替换账号。此证据支持网络环境丢失，不支持把错误归因于钉钉回调、内网 HTTP 或新 CLI 的授权码格式。

后续检测使用 `sandbox_command`，账号服务缺少执行器已有的显式 loopback 代理配置，因此也需要补齐。

## 修复步骤与验收

1. 登录子进程仅继承八个标准大小写代理变量；继续隔离其他宿主变量和凭据。对继承范围、解析与取消行为做回归。
2. 统一已有内网沙箱代理的显式 opt-in：仅配置 `HENGXIN_ALLOW_LOOPBACK_CODEX_PROXY=1` 才可在非开发环境使用已严格校验的 loopback HTTP/HTTPS 代理；默认行为保持。账号服务加入两项代理配置，继承工作节点已验证的部署行为。
3. 独立审查后备份并只部署账号 daemon 的两个源文件、其环境文件和持久化环境清单；暂停两业务消费、确认无在途任务，结束失败的登录尝试后确认账号空闲，重启账号服务并恢复消费。失败保留备份并安全恢复。
4. 真实 UID 从最终路径获取授权码并在回调后取消诊断；验证实际沙箱可通过代理访问授权站点、HTTP 健康与队列恢复。普通浏览器检查登录弹窗能显示官方授权链接和授权码。

完成账号的官方登录及确认启用由用户执行；不代替用户选账号、不把拿到授权码等同于账号已经登录成功。
