# 工作台消息署名与时间 · 批准开发并合并发布

最新授权：用户明确要求本次开发和测试完成后提交代码并部署生产。此授权恢复此前暂停的Git提交、生产部署及本轮OUTON Skill安装，合并既有三角色/字段调整、指定五人工作流权限，其他功能保持。

## 需求和数据口径

1. 用户消息头从固定“设计师”改为该条Turn.actor_id关联的实际成员姓名，展示该条消息created_at。不是当前查看人、任务创建人或负责设计姓名；多人消息分别展示。成员姓名使用现有身份记录，缺失或空白显示“未知操作人”，不编造历史姓名，不修改历史消息。
2. Codex保留名称和当前状态，显示对应回复时间。优先使用与当前实际回复内容匹配的最近公开message记录时间；reply为空但已有公开message时，使用实际可见最后一条message时间，包含运行中过程组的消息；旧回复无对应记录时，以该轮真实completed_at显示“完成于”，明确区别。无真实时间显示“时间未记录”；尚无回复时不虚构回复时间。不使用可被重试、归档或文件收取改变的updated_at。
3. 接口提供actor{id,name}、replyAt、replyTimeSource（message/completed/null）；时间输出带明确时区，SQLite/旧无时区数据库值按既有UTC存储语义处理。前端统一复用formatBeijingTime，显示YYYY-MM-DD HH:mm:ss，北京时间，不受浏览器时区影响。旧接口缺字段允许降级未知，不用当前用户或当前时间替代。
4. 保持消息内容、执行过程折叠、滚动、附件/图片、只读与五人权限；仅消息头补充信息，沿用现有弱化文字样式，窄屏长姓名自动换行不溢出。
5. 无新增数据库字段或历史数据重写。真实历史数据与新增消息统一走相同读取逻辑；新增字段不会扩大读取权限或变更工作流。
