# 工作台文件输出与手动取回实施合同（2026-10-24）

用户已授权实施、真实事故回归、独立审查、中文 Git 提交、打包并部署生产。本合同覆盖旧规则中的图片格式限制、无限自动补收及收取失败锁死会话；保留图片工作台定位：图片可查看、修改、下载、归档；其他文件展示并下载。图片归档和任务完成规则沿用现有业务。

## 要解决的问题

本次事故中，模型已经正常结束；程序却把查看素材时出现的图片当成待交付图片，又让收图错误不断重试并转成执行状态不确定。应纠正输出识别和错误归属，不通过增加格式白名单或新的全局门槛解决。

## 最小改动

1. 自动收取只使用明确的最终文件链接，以及能够确认属于最终回复、能定位到本会话真实文件的原生附件。仅有生成事件和 savedPath 不等于最终交付；无法确认时正常结束回复，让用户手动选择。不把工具里看过的图片一概当成成品，不强制模型交固定 JSON 清单。没有文件的正常文字回复直接结束。
2. 文件按原始内容保存，格式不作为整轮成功条件。复用现有文件存储和附件卡片；可用图片接入已有预览、修改和归档操作，ZIP、文档和未知格式显示名称、大小、下载。预览失败时保留原文件下载，不把普通文件塞入必填图片宽高的记录。
3. 每轮自动收取执行一轮，有明确结束；逐文件记录结果，成功的立即保留，失败的显示具体原因和手动入口。移除因此产生的无限补收和“执行不确定”。确认模型正常结束后，文件保存失败不再锁死聊天。服务重启先核实原执行和已有保存结果，确认模型已结束的轮次只核对原收取结果，未收妥项可手动重试，不重跑模型或恢复无限补收。真正的模型执行异常仍按实际状态处理。
4. 复用现有本轮副本能力，保护已明确识别的输出，再进入下一轮；后续上传失败仍可从副本取回。如果本轮副本也未保存成功，要如实显示，没有副本的原件不承诺防覆盖。不增加全工作目录历史版本系统。
5. 增加普通用户可使用的“取回文件”：列出本会话仍存在的工作文件、已关联原生会话的生成图片，以及尚未收妥的本轮副本。用户勾选后直接保存文件，复用自动收取的保存步骤，绕开自动识别器。无需管理员权限或全局暂停，不重跑模型。会话正在写文件时，等待本会话停止再取；其他会话和已保存结果照常使用。
6. 重复取同一版本返回已有结果；同路径内容变了就是新版，后续正式轮次再次交付也保留轮次关系。手动新增选择用独立收取记录，不修改旧轮已经固定的输出清单。沿用当前会话权限、文件范围和原件 500 MB 上限；不套用旧图片解码的 10 MiB 限制，无法进入图片操作的文件仍可按原件下载，0 B 文件如实展示。新增收取记录与存储对象纳入现有删除清单，删除已受理后拒绝迟到发布。任务完成态沿用只读，已有文件可下载，解冻后可继续取回；普通文件收取失败不增加任务完成条件。不允许通过手动入口读取其他会话或系统配置。

## 用户看到的效果

| 场景 | 预期结果 |
| --- | --- |
| 只让模型学习资料、只回复文字 | 回复结束后可以继续发消息，不等待不存在的图片。 |
| 输出图片和压缩包 | 图片进入现有图片操作区；压缩包显示文件卡片并可下载。 |

## 实施验收

使用本次真实事故输入验证：模型执行一次、普通回复正常结束、下一轮可以提交；混合输出验证图片操作和普通文件下载；模拟部分保存失败后手动取回；验证原生图片目录、预览失败下载、重复点击及同名新版；验证其他文件不会进入图片归档或改变完成规则。

任何文件未生成、已删除或已覆盖且没有副本时，明确说明无法取回。此方案不承诺恢复不存在的文件。

## 执行计划与完成标准

生产目录实查补充：API 容器的执行目录与原生执行器的宿主目录并不共享，且原件目录保持私有权限。因此“取回文件”复用已有 Redis 和原生 outbox 维护进程传递短时请求，原生侧调用同一列举、鉴权和保存代码；API 只传任务、会话、候选 ID 和版本并接收结果，不挂载私有目录、不放宽权限、不传文件内容、不新建模型任务。通道不可用或超时时明确提示稍后重试，已保存原件靠现有去重保留。

1. 同步源文档与数据合同：普通输出独立保存，不冒充输入素材或图片；保留旧图片兼容和归档完成规则。
2. 后端复用逐文件快照和对象台账，新增普通输出存取，自动收取有终态，修复素材误识别；事故输入、混合文件、失败与重启测试通过。
3. 手动入口直接列出并保存本会话文件与副本，复用同一保存逻辑；权限、原生目录、重复取回、同名新版和删除测试通过。
4. 前端复用附件卡片和图片操作，增加取回入口；预览失败原件下载、空态、失败态、取回交互和构建通过。
5. 完整相关回归、真实事故原始记录回放及独立两阶段审查；修复失败项后固定批准快照，中文提交已审文件，不包含用户 AGENTS.md 修改。
6. 按现有海外发布流程打包、检查安装产物、备份、停止接纳并排空、迁移和切换，验证正式入口、图片下载和取回入口。不得强停状态不明执行；保留国内业务、身份配置及 Skills。

职责：主 Agent 负责文档、共享保存核心、模型识别、状态、迁移、清理、整合与发布；独立执行 Agent 可分别负责手动取回新模块及前端，文件所有权明确，不提交；审查由 fresh code-reviewer 执行。
