# 工作台完成与解冻正式实施

用户确认 preview-studio-reopen 交互，授权正式开发、中文Git提交、打包和生产部署。预览不进入生产构建，正式界面使用真实API与状态。

## 验收合同

1. 完成任务：无活动执行且至少一张有效归档图片时改为completed，四步全部完成；历史聊天、素材和图片可读，写操作锁定，提供独立“解冻工作台”和“查看归档成品”。确认提示可再次解冻。
2. 解冻：二次确认，completed回studio，第③步继续设计，第④步有有效归档时显示已有归档，第①②步不重走。沿用任务设计权限及当前归属；删除中/失败/已删除、旧工作流、未审核通过均拒绝。保留当前Conversation/session_id、持久文件、历史、草稿及归档；解冻不发模型请求、不创建会话。后续发送沿现有resume；原会话不可用拒绝静默换会话。
3. 完成/解冻均服务端事务、幂等、任务锁与版本检查，旧页面不能覆盖新状态。网络未知结果同请求核实重试；真实操作者/时间/动作记录到现有TaskEvent；可重复循环，重复请求不重复变更/审计。
4. 新图由设计选图归档，不自动覆盖旧成品。归档入口定位本任务真实归档ID、复用正式成品详情/下载/原任务入口，不靠品名搜索。归档不存在/删除中如实反馈；无有效归档时再次完成须先归档；解冻不依赖归档仍存在。删除归档不得自动将已完成Studio任务解冻（替代旧清理中的自动回studio行为），仍需主动解冻；legacy流程保持。
5. 页面及列表真实状态同步，已完成页能感知其他成员解冻。活动/无权限/待核实时正确禁用；开始新对话仍为独立显式切换。遵循预览与原样式，窄屏和加载/错误提示完整可见。

## 接口与分工

- Studio响应新增taskVersion（正整数）、archiveId（有效可用归档ID或null）、reopened（有解冻历史）。
- POST studio/complete及新POST studio/reopen请求{version:正整数}；会话创建仍为空对象。版本冲突409提示刷新，幂等操作分别studio_complete/studio_reopen；空完成请求不能绕过版本校验。
- 后端worker负责backend业务与相关测试，前端worker负责frontend正式src与测试；主Agent负责文档/版本/发布工具/集成及生产。worker不提交、不spawn，不覆盖他人修改，契约变化先沟通。

## 有序计划与完成标准

1. 同步文档并只读核实生产版本、迁移、服务、在途任务。
2. 前后端独立实现自测：正常闭环、权限、重复/并发/版本冲突、会话和归档保留、归档缺失、请求失败和加载。
3. 全套回归、类型/生产构建、隔离真实HTTP/数据库和浏览器闭环；隔离协议验证相同会话resume。生产不以用户任务做状态变更或收费模型测试。
4. 固定快照、fresh code-reviewer两阶段审查、修复复验、中文Git提交。包隐私/依赖审计、实际镜像安装测试；生产排空、备份恢复验证、切换、健康/版本/源码/正式页面验收；保护国内、身份、凭据代理及历史会话，失败按阶段处理。
