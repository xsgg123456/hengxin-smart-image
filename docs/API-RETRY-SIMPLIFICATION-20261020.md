# 国内 API 提示简化与取消人工核实

2026-10-20 用户在真实前端十五场景预览后授权正式实施。仅国内 API 换套图；本轮是代码修改与隔离验证，不执行生产部署。既有预览演示栏、模拟数据和定时器不得进入正式代码。

## 范围与覆盖关系

- 前端提示简单，不叠技术词语：整体进度一处，每图简短状态；未完成直接给单张/批量重试入口。成功结果保留；批量重试只处理符合条件的未完成图片，不重新提交成功或仍在处理的图片。
- 取消 API 调用结果异常后的管理员人工核实门槛，包括页面、接口依赖和既有卡住记录的恢复。仅本地调用已结束或原有租约失效的调用进入既有恢复/重试路径；有效执行权、同图互斥和旧执行者提交屏障保留。不能声称已确认上游停止或保证上游没有重复计费。
- 已持久化结果的下载、收集、保存继续走原收图路径，不能因取消核实重新生成。历史终态图片关联的旧 uncertain 审计记录不自动重做、不删除。
- 明确保留：每新轮最多20次、首次发送后45分钟、300秒请求超时、600秒租约、原退避及 Retry-After、全局每5秒一个新发送/在途10、任务/批次调度、冷却与单探测、冻结输入/版本、幂等与停止语义。账号/余额/参数等原有不可重试分类不扩大。
- 原整套重试只允许任务已结束（failed/partial_failed），这一后端资格保持；混合处理中任务可对已失败图片单张重试，批量入口等任务结束后出现。此项按用户最终“不改其他后端逻辑”的范围收紧先前模拟预览。
- 不修改海外、CLI 执行/取消/恢复协议和其独立核实机制，不删除这些模块的保护。
- 本合同覆盖 `API-RETRY-PLAN-20261020.md` 中“API未知结果必须管理员核实后才可恢复”及技术提示展示要求；其余条款保持。历史发布记录仅作为原实现记录。

## 正式页面验收

沿用现有导航、记录列表、详情抽屉、图片卡片及样式。复用已确认预览的提示层级，不新增设计。

1. 整体只给一句进度，如“已完成6/11张，其余正在生成/自动重试/保存”；全失败不显示“部分已完成”；服务繁忙、不可用分别简短说明。
2. 每张图显示等待中、生成中、重试中、保存中、已完成、未完成或已停止之一；失败直接显示“重试这张”，多张提供“重试未完成的N张”。未决提交沿用原幂等键重试确认，不能把响应丢失当作新请求。
3. 移除“需核实/核实已停止”、重复技术警告、尝试计数/发送名额/探测术语；不让用户承担后台状态管理。保留必要的停止按钮和原真实操作。
4. 刷新失败保留上次数据，明确是刷新失败；下载失败不标成生成失败；重试提交失败提供简短可操作提示。真实错误信息留在内部诊断，不将上游原始响应显示给用户。
5. 正常、繁忙、自动重试、保存、部分/全部未完成、混合、停止、完成、原卡住状态、刷新/下载/提交失败及不可用场景具备验证；桌面和390px窗口均可操作。

## 有序实施与完成标准

1. 同步源文档与当前计划，固定边界；完成标准是上述范围可对应源码和测试。
2. 后端仅改人工核实恢复链及相关接口；完成标准是异常结束/租约恢复/既存状态不再依赖管理员，既有重试参数、有效调用保护、历史成功结果及迟到隔离的回归通过。
3. 前端接真实状态与操作；完成标准是复用真实组件、无演示模块，失败入口直接可用且不越过后端权限/并发/幂等。
4. 运行前后端全量回归、类型/构建、隔离数据库并发与真实浏览器核心流程，固定快照独立两阶段审查；完成标准是报告无开放阻塞，证据可追溯。不触发真实收费生成。
