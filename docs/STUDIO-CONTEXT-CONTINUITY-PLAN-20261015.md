## 2. 根因链路

1. `backend/app/overseas/studio/service.py:51–65`：作业只冻结本轮主动选择的附件和引用图片。这个规则能防止未选资料被自动读入，但现有实现没有另行保留已提供文件的连续访问能力。
2. `backend/app/overseas/studio/execution.py:19–44`：按 conversationId 复用 HOME 与 sessionId，第二轮确实调用 resume。
3. `backend/app/execution/workspace.py:31`：工作目录按 turnId 建在 `rounds/<turnId>`；`:91–92` 只把当前轮目录绑定到 `/work`，旧轮目录不在沙箱可见范围内。
4. `backend/app/overseas/studio/execution.py:49–69`：只把本轮 inputs 写入当前目录，并用 `1.pptx` 等轮内编号命名。第二轮没有附件，就得到空 inputs。
5. 模型记得之前的文件路径，继续读取时路径却映射到另一份目录，形成“记得需求、读不到资料”的断档。

本地直接调用实际 `prepare_workspace`，先在第一轮放入附件和提取图片，再创建同会话第二轮，复现结果为：HOME相同、work不同、旧文件仍在、第二轮原路径均不存在。该复现没有调用模型。

既有测试 `backend/tests/test_overseas_studio_execution.py:66–82` 只验证首轮附件、session resume和状态，还明确断言两轮work不同；没有断言第二轮能读到首轮文件。这解释了为何原测试通过而实际续聊失败。

发布发生在两轮之间，但当前证据不支持“发布删除了资料”：旧文件仍完整，且创建新work的行为属于已有实现。

## 3. 需要分开的其他现象

**Skill文件未挂载。** 第二轮冻结输入中的 `skill=null`。`overseas/execution/materials.py` 只准备本轮所选Skill，沙箱也隐藏旧发现目录。当前Spec规定每轮主动选择，不能把空值擅自解释为继续调用旧Skill。前端发送成功保留内存中的选择，但重新进入页面时从空值初始化；目前不能仅凭日志断定用户为何没有选择。

**字体真实缺少。** 两轮日志均表明指定的汉仪旗黑X1、Segoe UI未找到；第二轮列出的系统字体为DejaVu。文件连续性修复不等于字体已经安装。后续应检查有授权的字体是否存在于本会话素材中，仍缺少再单独列缺项。

**Logo和清晰本品图是否足够，尚未验收。** 旧PPT和提取图可恢复，但不能据文件数量断言生产素材充足。应先恢复和核查已有内容，再决定是否需要新增素材，避免要求用户重传已经存在的PPT。

**执行成功与交付成功不同。** 第二轮CLI确实正常回复，因此作业为succeeded；它没有完成A+出图。不能把本次改成“所有追问都算执行失败”。

## 4. 推荐方案：同一会话持续使用自己的工作目录

### 4.1 生命周期和隔离

海外Studio新增会话级持久work，逻辑路径始终为 `/work`。同一conversationId的后续轮次继续读写该目录，附件、提取图片、脚本、研究笔记和未交付中间文件连续可用。

实施宿主布局（首次迁移以整个persistent目录原子启用）：

```text
execution/studio/<conversationId>/
  home/                    # 现有会话HOME
  persistent/
    work/                  # 会话持续工作内容，挂载为 /work
    inputs/                # 已授权原件，按版本存放，向 /work/inputs 只读挂载
    context-index.json     # 向 /work/.context-files.json 只读挂载
    manifest.json          # 私有来源和迁移记录，不挂载给模型
  rounds/<turnId>/          # 本轮冻结Skill等准备内容；兼容保留旧轮目录
  control/<turnId>/         # 本轮输入快照、日志、退出记录、输出基线
```

开始新对话创建新conversationId和独立work；任务材料仍可由用户明确选择后引入。其他任务和其他会话的目录不挂载。任务删除继续按数据库确定的conversation归属清理整个会话根目录，归档成品保留独立存储版本。

只让Studio使用这一布局；共享工作区函数的国内任务、海外旧分析/生成/修改流程保持各自既有行为，并进行回归。

### 4.2 原件路径、版本与恢复

- 已经提供给当前对话的文件持续可读；任务侧栏中从未提供给此对话的资料不自动加入。
- 附件按资源类型、ID及内容版本建立稳定路径，如 `/work/inputs/<assetId>/<checksum>/<safeName>`，同名不同文件和再次引用均不会覆盖历史内容。
- 原件在persistent/inputs中保存为受控只读文件；模型在work中另建编辑副本。读取既有文件时验证归属和完整性，原件缺失时从对象存储恢复并校验；存储确实缺失时给出具体文件错误。
- `/work/input.json` 由本轮control快照只读挂载，防止共享work里的旧文件或链接影响下一轮准备。输入和Skill等受控路径必须做链接及越界校验，不向模型暴露control目录。
- 不每轮重新复制全部历史文件。原件按版本复用，迁移复制只发生一次；执行前检查空间，空间不足明确阻止新执行，不自动清掉当前会话资料。

### 4.3 Skill的处理

本次核心修复保持“本轮选择决定本轮Skill”的契约：在每轮独立准备目录冻结完整Skill，向 `/work/skills` 和发现目录挂载当前所选版本，旧版本不因work持久化而意外暴露。没有选择时这两个入口为空。Skill自己的脚本和参考资源必须随冻结版本一起挂载。

建议附带一项明确的交互改进：按操作者、任务、conversationId记住用户主动选择的Skill，重新打开页面仍显示同一选择；用户主动清空则保持“无Skill”，开始新对话重置，原Skill失效则提示重新选择。后端继续按可见选择冻结，不依据历史文字暗中添加Skill。此项会改变刷新后的选择持久性，实施前要补入Spec与对应前端验收。

### 4.4 图片收取必须同时适配

持久work中会存在历史图片，不能直接沿用“当前work里的图片都来自本轮”的假设。

继续只接收本轮最终回复明确交付的合法图片，并为work里的候选图片保存执行前基线，区分新增、已修改和未变化的历史文件；历史文件仅被引用时不能直接记作新生成成品，原件和Skill资源始终不能充当输出。基线遍历只用于归属/版本校验，不用于自动发现并展示图片。

修改后生成的新版本使用独立对象存储记录；已归档版本保持原字节。保留现有CLI生成图片目录的session归属和历史输出门禁。这样既能续改上一轮图，也不会因共享work让旧草稿或旧成品重复冒充新交付。

## 5. 旧会话与本次任务恢复

不能只让新会话正常。升级时在无在途执行的条件下，为旧conversation生成只读迁移清单，再按归属和校验值恢复文件。

1. 枚举数据库关联的历史turn、冻结附件、该会话各轮work和会话文件，保存源文件清单、校验值、目标路径及冲突项。
2. 已有原件按稳定版本路径保存；研究文件按原相对路径恢复。多个旧轮次存在同路径不同内容时，分别保留来源版本，输出路径索引；不能盲目覆盖并让模型误读另一版本。
3. 无冲突的旧路径保留兼容入口；有歧义的旧路径不静默选一个版本，使用明确的新路径映射。在首次升级续接中仅提供必要的恢复路径信息，用户消息和已有会话保持。
4. 迁移在临时目标准备并校验，完成后原子启用布局标记；失败不标完成，不破坏原目录，重复执行可验证并安全续行。复制不跟随符号链接，不用硬链接共享可修改数据。
   迁移日志尚未提交时，重试必须继续提供恢复索引提示；即使文件复制已完成、重试无需新增复制，也不能视为提示已送达。提示只在后续真实执行进入历史后消除。
5. 本任务第一轮资料完整、第二轮无新素材，具备恢复来源。保留现sessionId，恢复原附件与研究目录后可继续；无需重新上传原PPT/Excel，也无需重跑第一轮。Skill按界面明确选择，字体与素材充足性单独检查。

只升级代码不会自动把旧目录变成新布局，因此迁移/恢复必须作为交付项。回退旧版本后若又新增轮次，要重新盘点增量，不能继续信任旧迁移标记。本方案阶段未执行任何恢复写入。

## 7. 方案取舍与当前边界

推荐会话级持久work。每轮重新下载所有附件只能补原件，不能补研究文件和中间产物；每轮复制全部旧work会随轮数增加磁盘与I/O开销。本任务第一轮已约255MB，复制方案没有必要。

临时绕行可在右侧重新引用现有两份材料并重新选择A+ Skill，无需重新上传；它会重新准备原件，但不能恢复原有研究文件，也不能解决下一轮再次断档。当前优先实施持久工作区和历史恢复。

用户随后授权实施，本轮已同步Product-Spec/DEV-PLAN并实现持续目录、旧文件迁移、正式图片版本门禁及受限恢复工具。前端364项测试和正式构建通过；实际生产Linux环境隔离沙箱三轮读取通过，没有调用模型或改动业务文件。全量回归、独立审查与生产切换/历史恢复按上述顺序执行，最终证据另记录验收文档。
